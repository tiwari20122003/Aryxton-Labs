## What Does Aryxton Labs Actually Audit?

| **Pillar**       | **What it checks**                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **SEO Health**   | Titles, meta descriptions, H1, canonical, Open Graph, Schema.org, image alt text, broken links, and internal/external link counts     |
| **Security**     | SSL/TLS chain & expiry, OWASP security headers, phishing heuristics, malware signals, hidden iframes, **`eval`**, and exposed secrets |
| **Performance**  | Per-page load time, estimated LCP, page weight, and PageSpeed-style scoring                                                           |
| **Domain Intel** | WHOIS registrar/dates, nameservers, MX records, A records, **`robots.txt`**, and **`sitemap.xml`**                                    |
| **AI Copilot**   | Prioritised, human-readable action plan generated by an LLM through OpenRouter                                                        |
| **Export**       | Multi-sheet **`.xlsx`** export containing Overview, Pages, Issues, Performance, and Security                                          |

## Key Engineering Principles

### 1. Defense in Depth

SSRF protection is applied across multiple layers:

- **`cyber_scanner`**
- **`server._normalize_target`**
- **`whois_dns`**
- **`crawler`**

This prevents a single missed validation path from exposing internal resources.

### 2. Graceful Degradation

The core audit remains functional when optional services fail.

- AI is optional.
- MongoDB is optional.
- Screenshot generation is optional.
- Third-party failures are handled gracefully.

### 3. Bounded Work

Every request operates within explicit resource limits:

- **2 MB** maximum HTML per page
- **25 pages** maximum per audit
- **8-second** outbound request timeouts
- **75-second** AI timeout
- Per-IP rate limiting

These limits reduce the risk of a single request exhausting server resources.

### 4. Clean API Contract

The backend provides:

- Typed Pydantic request/response models
- Structured JSON errors
- Configurable CORS
- FastAPI Swagger documentation
- FastAPI ReDoc documentation
- Request tracing IDs

## Quick Start

### Prerequisites

- **Python 3.10+**
- **Node.js 18+**
- **MongoDB 5+** — local or Atlas

MongoDB defaults to:

```text
mongodb://localhost:27017

```

### ① Backend

```bash
cd backend
python -m venv .venv

```

**Windows:**

```bash
.venv\Scripts\activate

```

**macOS/Linux:**

```bash
source .venv/bin/activate

```

Install dependencies:

```bash
pip install -r requirements.txt

```

Copy the environment file:

**Windows:**

```bash
copy .env.example .env

```

**macOS/Linux:**

```bash
cp .env.example .env

```

Optionally add your OpenRouter API key to enable AI insights.

Run the API:

```bash
uvicorn server:app --reload --host 0.0.0.0 --port 8000

```

Open:

```text
http://localhost:8000/docs

```

You should see the FastAPI Swagger UI.

---

### ② Frontend

```bash
cd frontend

```

Copy the environment file.

**Windows:**

```bash
copy .env.example .env

```

**macOS/Linux:**

```bash
cp .env.example .env

```

Install dependencies:

```bash
npm install

```

Start the development server:

```bash
npm run dev

```

Vite normally runs at:

```text
http://localhost:5173

```

For legacy CRA-style workflows:

```bash
npm start

```

That's it. Open the UI, paste a URL, and click **Analyse**. 🎉

## Production Build

### Frontend

```bash
cd frontend
npm run build

```

The production build can be served using:

- Nginx
- Caddy
- Vercel
- Netlify
- Any static hosting provider

### Backend

```bash
cd backend
pip install gunicorn

```

Run with Gunicorn:

```bash
gunicorn server:app \
  -w 4 \
  -k uvicorn.workers.UvicornWorker \
  -b 0.0.0.0:8000

```

Alternatively, use a process manager such as:

- systemd
- PM2
- Supervisor

### Reverse Proxy

For a production deployment, serve the frontend and backend behind the same domain:

```text
/        → React static build
/api/*  → FastAPI

```

Example backend target:

```text
http://127.0.0.1:8000

```

This keeps the browser-facing application on a single origin and simplifies CORS configuration.

## Production Security Checklist

### Implemented

- **SSRF protection** — private, loopback, and cloud metadata IPs blocked across multiple layers
- **Input validation** — Pydantic domain validation and **`max_pages`** clamped to **`1–25`**
- **Content-size cap** — 2 MB maximum crawled HTML per page
- **Prompt-injection guardrails** — AI input/output validation and sanitisation
- **Rate limiting** — per-IP protection through SlowAPI
- **Secret-safe logging** — API keys are never logged
- **Configurable CORS** — controlled through **`CORS_ORIGINS`**
- **XSS-safe Markdown rendering** — React rendering without unsafe **`innerHTML`**
